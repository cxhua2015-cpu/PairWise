# inventory

并发安全的内存型库存计数账本（Go 1.22+，仅标准库）。语义见 `SPEC.md`。

## 设计说明

- **索引**：账户主存储为 `map[string]Account`（按名称 O(1) 定位）。`Top` 与 `Snapshot` 不维护持久有序索引，而是每次调用时对当前账户快照就地排序——写路径保持 O(1)，读路径付出代价，避免在每次写入时维护堆/有序结构的复杂度。
- **候选事务**：`Apply` 先对整个批次做纯结构校验（kind、名称），不读状态；随后在仅覆盖被触及账户的候选缓冲（`pending`/`exists` 映射）上按输入顺序执行 Add/Set/Delete。溢出与绝对值上限在算术前检查，账户容量在批次末按最终净额检查。任何失败直接丢弃候选缓冲即完成回滚，无需逆向补偿；全部通过后才一次性提交并递增 `generation`。
- **所有权**：所有公开方法共用一把 `sync.Mutex`，调用期间账本状态不被并发修改。`Result.Changed`、`Top`、`Snapshot` 返回的切片均为新分配的拷贝，调用方修改不会影响内部状态；内部也绝不保留调用方传入的切片。
- **复杂度**：设批次长度 B、账户数 N、Top 请求 k。`Apply` 为 O(B)（外加 O(N) 的最终容量计数，可优化为增量但保持简单）；`Top` 为 O(N log N) 时间、O(N) 额外空间；`Snapshot` 为 O(N log N)（按名称排序）；`New` 为 O(1)。
