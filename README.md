# pathrouter

Go 1.22+ 标准库实现的并发安全动态路径路由器，适用于边缘网关场景。公开 API 与错误语义见 `SPEC.md`。

## 模式表示

- 模式必须以 `/` 开头；`/` 为根模式（零段）；其余模式由非空 `/` 分隔段组成，不允许尾斜杠与空段。
- 段分三类：静态段（注册时用 `url.PathUnescape` 解码，解码结果非空、不为 `.`/`..`、不含 `/`）、`:name` 单段参数、`*name` 末尾 catch-all（匹配一段及以上）。
- 参数名须为 `[A-Za-z_][A-Za-z0-9_]*`，同一模式内不得重复。
- 内部把每个模式编译为段序列（kind + 解码字面量 + 参数名），匹配在解码后的请求段上进行。

## 冲突检测

- 路由名全局唯一（跨方法）。
- 结构形状（shape）按方法隔离：逐段的（静态解码值 / 参数 / catch-all）序列相同即冲突，与参数名无关，例如 `GET /users/:id` 与 `GET /users/:name` 冲突，但 `POST /users/:name` 不冲突。
- 校验顺序：先做结构校验（方法 → 模式），再做冲突/未找到检查，容量检查最后。

## 匹配优先级

- 候选按段 kind 从左到右字典序排名：静态 < 参数 < catch-all；公共前缀 kind 相同时，非 catch-all 段更多者胜。注册顺序不影响选择。
- 同形状路由因冲突检测而唯一，因此排名结果完全确定。

## HEAD 与 Allow 语义

- 路由不能注册 `HEAD`；请求方法 `HEAD` 合法，先尝试精确方法，未命中回退到 `GET` 并置 `HeadFallback=true`。
- 所选方法无匹配但其他方法的路径匹配时，返回 `MethodNotAllowed=true`、`Found=false`，`Allowed` 为排序去重后的方法集合；若含 `GET` 则附加 `HEAD`。

## 批量事务

- `Apply` 等价于单元素 `ApplyBatch`。
- 批次在隔离的候选状态（索引映射的写时复制）上按输入顺序逐条执行；后续变更可删除同批次先前添加的路由、释放名称/形状。
- 任一变更失败即整体回滚并返回零值 `UpdateResult`；`MaxRoutes` 只对最终候选状态生效，中间可暂时超限。
- 成功的非空批次使 generation 恰好加一；空批次成功且不改 generation。

## 反向构造

- `Build(name, params)` 按全局名称查路由，参数键必须与路由参数集合完全一致。
- 单段参数值非空、不含 `/`、不为 `.`/`..`；catch-all 值须为一段及以上合法段。每段用 `url.PathEscape` 转义，结果可经 `Match` 无损往返。

## 所有权

- 插入时复制 `Value`；`Match`、`Snapshot` 返回的 `Value`、`Params`、`Routes` 均为深拷贝，与输入、内部状态及其他返回值互不影响。

## 并发

- 所有公开方法可并发调用。读路径（`Match`/`Build`/`Snapshot`）使用 `sync.RWMutex` 读锁，写路径（`Apply`/`ApplyBatch`）使用写锁；批次在锁内对克隆索引操作，提交时一次性替换。

## 复杂度

设 R 为路由数、S 为路径段数、L 为单段平均长度、B 为批次大小：

- 注册/批次：结构校验 O(模式长度)；批次克隆索引 O(R)，逐条变更 O(模式长度)，提交 O(1)；整体 O(R + B·模式长度)，额外空间 O(R)。
- `Match`：路径解码 O(S·L)；候选扫描 O(该方法路由数 × S·L)；405 聚合 O(R × S·L)；空间 O(S)。
- `Build`：O(模式长度)；`Snapshot`：O(R log R) 排序，空间 O(R)。
- 内存：每路由 O(模式长度 + Value 长度)。
