# pathrouter

Go 1.22 标准库实现的并发安全动态路径路由器，位于 `router` 包。公开 API 与错误语义见 `SPEC.md`。

## 模式表示

模式在注册时解析为段（segment）列表，每段为三种之一：

- 静态段：注册时用 `url.PathUnescape` 解码并校验（非空、非 `.`/`..`、不含 `/`），内部保存解码后的文本；
- 命名参数 `:name`：匹配单个段，名称为 `[A-Za-z_][A-Za-z0-9_]*`，同一模式内不得重复；
- 末尾 catch-all `*name`：必须是最后一段，匹配一个或多个剩余段。

`/` 是根模式（零段）；其他模式以 `/` 开头、段非空且不以 `/` 结尾。

## 冲突检测

每个模式生成结构形状键：静态段携带解码文本，参数与 catch-all 只记录种类（忽略参数名）。同一方法下形状键相同即冲突（如 `/users/:id` 与 `/users/:name`），不同方法互不影响。路由名称在全局唯一表中检查。两者均返回 `ErrConflict`，且结构校验先于冲突/未找到检查。

## 匹配优先级

请求路径先逐段解码校验（非法转义、空段、`.`、`..`、解码出 `/` 均返回 `ErrInvalidPath`）。候选路由按逐段种类字典序比较：静态 > 参数 > catch-all；公共前缀种类相同则非 catch-all 段多者胜。该比较构成全序，与注册顺序无关，保证选择稳定。

## HEAD / Allow 语义

路由不能注册 `HEAD`；请求方法 `HEAD` 先尝试精确匹配，再回退到 `GET`，命中时 `HeadFallback=true`。所选方法无匹配但其他方法的路径匹配时，返回 `MethodNotAllowed=true`，`Allowed` 为排序去重后的方法集合，且只要 `GET` 在内就附加 `HEAD`。所有方法都无匹配时两个标志均为 false。

## 批量事务

`ApplyBatch` 在克隆的隔离状态上按输入顺序逐条执行（`Apply` 等价于单元素批次）。后续变更可以删除本批次早前添加的路由、释放名称/形状供复用。任何错误整体回滚并返回零值 `UpdateResult`。`MaxRoutes` 只对最终候选状态检查（超限返回 `ErrCapacity`），批次中间可临时超限。非空批次成功时令代数恰好加一；空批次成功且不改代数。

## 反向构造

`Build(name, params)` 按全局名称查路由，要求参数键与模式参数完全一致（缺失或多余返回 `ErrInvalidParams`）。单段参数值须非空、非 `.`/`..`、不含 `/`；catch-all 值按 `/` 拆分后逐段校验。每段用 `url.PathEscape` 转义拼接，保证结果路径经 `Match` 往返后解码参数值不变。

## 所有权

插入时拷贝 `Value`；`Match`、`Snapshot` 返回的 `Value`、`Params`、`Allowed`、`Routes` 均为深拷贝，与输入、内部状态及其他返回值互不影响。内部路由条目创建后不可变，批次克隆只复制映射与切片，不复制条目本身。

## 并发与复杂度

全部公开方法可并发调用：写操作（`Apply`/`ApplyBatch`）持互斥锁，读操作（`Match`/`Build`/`Snapshot`）持读写锁的读锁。

设 R 为路由数、L 为路径段数、M 为方法数、B 为批次大小：

- `Match`：时间 O(R·L)（每方法线性扫描候选并取最优），空间 O(L)；
- `ApplyBatch`：时间 O(R + B·L)（克隆状态 + 逐条校验执行），空间 O(R)；
- `Build`：时间 O(L)，`Snapshot`：时间 O(R log R)（按名称排序）；
- 总存储：O(R·L)。
